### Conventions

#### Database
- **All tables** are defined in `src/database/schema.ts` — never scatter table definitions across modules.
- **UUIDs**: `varchar(36)` with `$defaultFn(() => randomUUID())` — application-generated, not Postgres sequence.
- **Money**: `numeric(precision, scale)` — NEVER float/double for currency.
- **Location**: `geography(Point, 4326)` custom type — use `sql` template tag for PostGIS functions.
- **Timestamps**: Always use `withTimestamp()` helper when updating rows — Drizzle does NOT auto-set `updated_at`.
- **Idempotency**: All financial operations (`transactions`) must use a unique `idempotency_key`.
- **GiST indexes**: Cannot be auto-generated by Drizzle Kit. Apply `drizzle/gist_indexes.sql` manually on new databases.
- **Migrations**: Never use `db:push` in production. Use `db:generate` → review → `db:migrate`.

#### Security
- **Auth guard**: ALL new endpoints must use `@UseGuards(JwtCookieAuthGuard)` unless explicitly public.
- **DTO validation**: `ValidationPipe` is global with `whitelist: true`, `forbidNonWhitelisted: true`, `transform: true`. Create strict DTOs with `class-validator` decorators.
- **JWT**: Stored EXCLUSIVELY as `HttpOnly; Secure; SameSite=Strict` cookie. NEVER returned in response body.
- **OTP**: 6-digit, 5-minute expiry, CSPRNG-generated (`crypto.randomInt`). In-memory Map (dev) — Redis before production.
- **CORS**: Whitelist only `PLAYER_URL` and `ADMIN_URL`. Wildcards forbidden.
- **Rate limiting**: Global 60 req/min. Add per-route `@Throttle()` on sensitive endpoints (OTP).

#### API Patterns
- **Authentication flow**: `POST /auth/send-otp` → `POST /auth/verify-otp` → (if `isNewUser`) `PATCH /auth/complete-profile`
- **Nearby matches**: `GET /matches?lat=&lng=&radius_km=&date=` — uses PostGIS `ST_DWithin` on geography column. Cached in Redis for 60s.
- **Match detail**: `GET /matches/:id` — returns full relations (host, pitch, venue, players).
- **Wallet**: Service layer is complete (append-only ledger, idempotency, balance guards). Controller endpoints NOT yet exposed — use `WalletService` directly from other services.
- **WebSocket**: `/lobby` namespace. Emit `join-lobby` before `send-message`. Listen for `new-message`, `user-joined`, `roster-update`.

#### NestJS Patterns
- **Module imports**: Use `DatabaseModule` (global) for DB access. Inject `@Inject('DB_CONNECTION')`.
- **Service injection**: Constructor injection with `private readonly` convention.
- **Error handling**: Use NestJS exceptions (`BadRequestException`, `NotFoundException`, `UnauthorizedException`, etc.) — never raw `throw new Error()`.
- **Logging**: Use `Logger` service — NEVER `console.log`. Pino formats JSON in production.

### Conventions

#### Routing & i18n
- **ALL pages** use `'use client'` directive (app is client-rendered PWA).
- **Locale**: Extracted from `usePathname()` as `pathname.split('/')[1]`. Always include `/${locale}` in Link hrefs.
- **RTL/LTR**: `dir` attribute set on `<html>` by root layout. Tailwind `ltr:`/`rtl:` variants available.
- **New pages**: Place under `app/[locale]/(main)/<route>/page.tsx`. The `(main)` layout wraps with MobileFrame + BottomNav.

#### State Management
- **Client state** → Zustand (`useAppStore`) — auth, preferences, filters, booked matches, balance, UI.
- **Server state** → TanStack React Query — matches, transactions, venues, messages. (Currently using `lib/dummy-data.ts` — MUST replace with `@tanstack/react-query` hooks.)
- **Persistence**: Zustand `persist` middleware with `partialize` — only persist client state (prefs, auth, booked IDs), NOT server data.
- **Selectors**: Use typed selectors (`selectLocale`, `selectUser`, etc.) to prevent unnecessary re-renders.

#### API Integration
- **All API calls** MUST use `lib/fetcher.ts`:
  ```typescript
  import { fetcher } from '@/lib/fetcher';
  const data = await fetcher<Match[]>('/matches', { params: { lat, lng } });
  ```
  - Auto-includes `credentials: 'include'` for JWT cookie.
  - Auto-prefixes with `NEXT_PUBLIC_API_URL` (from env).
  - Throws `FetchError` with `status` code on non-ok responses.
- **DO NOT** use raw `fetch()` directly anywhere in the app.

#### Design System
- **Primary brand color**: `brand-green` (#1B4332) — used for CTAs, headers, accents.
- **Background**: `brand-bg` (light gray) for main content areas.
- **Cards**: `bg-white rounded-2xl shadow-card` — the standard card pattern.
- **Buttons**: `bg-brand-green text-white rounded-2xl font-bold` — primary CTA.
- **Fonts**: Outfit (Latin) + Tajawal (Arabic) — both loaded with `display: swap`.
- **Mobile frame**: Always use `<MobileFrame>` for pages that need the phone-frame chrome. Layout groups provide this automatically.
- **Safe areas**: Use `pt-safe` and `pb-safe` Tailwind classes for notch/home-indicator padding.
- **Scroll containers**: Add `scroll-container` class for smooth momentum scrolling.

#### 5 Required States Per Screen
Every screen MUST handle all five states:
1. **Loading** — Skeleton/spinner while data is fetching
2. **Empty** — Friendly message when no data exists (e.g., "No matches nearby")
3. **Populated** — The normal data-filled view
4. **Error** — Error message with retry button when API/network fails
5. **Edge cases** — Partial data, missing avatar, long names, RTL text, etc.

#### PWA / Offline
- **Service worker**: `public/sw.js` (Workbox) — auto-generated at build time.
- **Offline page**: `app/[locale]/offline.tsx` — shown when network is unavailable.
- **Manifest**: `public/manifest.json` — icons must exist in `public/icons/`.
- **New routes/assets**: Must be added to the Workbox precache manifest (handled by Next.js build, but verify).

#### Testing
- **Framework**: Vitest
- **Location**: `test/*.test.ts` (unit) and `test/*.test.tsx` (component)
- **Coverage target**: All `lib/` utilities, auth flows, store slices.
- **CI**: GitHub Actions runs lint → type-check → test → build on PRs to `main`.

## PR Workflow (GitHub Flow)

1. **Create branch**: `feature/<short-description>` or `fix/<short-description>`
2. **Conventional commits**: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`
3. **Push**: `git push -u origin <branch>`
4. **Open PR**: `gh pr create --base main --title "..." --body "..."` (requires valid gh auth)
5. **PR body checklist**:
   - [ ] Build passes: `npm run build`
   - [ ] Tests pass: `npm test` (in each app)
   - [ ] All 5 UI states handled
   - [ ] API endpoints secured with JwtCookieAuthGuard
   - [ ] Drizzle migration generated (if schema changed)
   - [ ] i18n messages added for both ar/en
6. **CI must be green** before merge.
7. **Squash merge** to `main`.
