## 2. Backend (`apps/api`) — NestJS + Drizzle + PostgreSQL

### Architecture

```
apps/api/src/
├── main.ts                    # Bootstrap: helmet, validation, swagger
├── app.module.ts              # Root module
├── database/
│   ├── schema.ts              # Drizzle ORM schema (ALL tables + relations + enums)
│   └── database.module.ts     # DB connection provider
├── common/

│   ├── decorators/current-user.decorator.ts
│   └── utils/timestamp.ts               # withTimestamp() helper
└── modules/
    ├── auth/                  # Phone OTP → JWT → Complete Profile
    │   ├── auth.controller.ts
    │   ├── auth.service.ts
    │   ├── auth.module.ts
    │   ├── jwt-cookie.strategy.ts
    │   ├── unifonic.service.ts
    │   └── dto/
    ├── matches/               # Discovery feed + match detail
    │   ├── matches.controller.ts
    │   ├── matches.service.ts
    │   ├── matches.module.ts
    │   └── dto/
    ├── wallet/                # Ledger service
    │   ├── wallet.controller.ts
    │   ├── wallet.service.ts
    │   ├── wallet.module.ts
    │   └── dto/
    ├── venues/                # Venue discovery + detail
    │   ├── venues.controller.ts
    │   ├── venues.service.ts
    │   ├── venues.module.ts
    │   └── dto/
    ├── users/                 # User profile + stats
    │   ├── users.controller.ts
    │   ├── users.service.ts
    │   ├── users.module.ts
    │   └── dto/
    ├── gateway/               # Socket.IO /lobby WebSocket
    │   ├── app.gateway.ts
    │   └── gateway.module.ts
    └── health/
```

### Hard Rules

1. **All new endpoints MUST be guarded** with `@UseGuards(JwtCookieAuthGuard)` — unless explicitly public (health, auth steps).
2. **DTOs first**: every controller method must have a class-validator DTO for request bodies AND query params. Use `@ApiProperty()` decorators for Swagger.
3. **DB access pattern**: inject `@Inject('DB_CONNECTION') private readonly db: DB` where `DB = PostgresJsDatabase<typeof schema>`. Use Drizzle query builder unless raw PostGIS SQL is needed (use `sql` template tag).
4. **`updated_at` rule**: ALWAYS use `withTimestamp()` from `common/utils/timestamp.ts` for any `.update()` call — Drizzle does NOT auto-set `updated_at`.
5. **New services** go in `apps/api/src/modules/<name>/` with: `*.module.ts`, `*.service.ts`, `*.controller.ts`, `dto/`.
6. **Migrations**: NEVER use `db:push` in production. Edit `schema.ts` → `npm run db:generate` → review → `npm run db:migrate`. GiST indexes require manual SQL in `drizzle/gist_indexes.sql`.
7. **OTP store**: currently in-memory `Map` — MUST be replaced with Redis `SETEX` before go-live.
8. **Error handling**: use NestJS exceptions (`BadRequestException`, `NotFoundException`, `UnauthorizedException`). Never return raw strings.

```
├── components/
│   ├── layout/                 # MobileFrame, TopAppBar, BottomNav
│   ├── matches/                # MatchCard, TeamLineup, DatePicker, GameDetails, LocationMap, TeamLineupSheet
│   ├── host/HostMatchForm.tsx
│   └── payment/PaymentSheet.tsx
├── store/
│   ├── useAppStore.ts          # Zustand (preferences + slices)
│   └── slices.ts               # Auth, Match, Wallet, UI slices
├── lib/
│   ├── fetcher.ts              # Canonical API client (extend, don't replace)
│   ├── api-adapter.ts          # Snake→camelCase transformations
│   └── utils.ts                # Shared utilities
├── providers/QueryProvider.tsx  # TanStack Query provider
├── messages/                    # i18n — ar.json, en.json
├── types/index.ts
├── middleware.ts
└── i18n.ts
```

### Hard Rules

1. **ALL API calls go through `lib/fetcher.ts`**. Never use raw `fetch` in components. The fetcher handles: base URL, `credentials: 'include'`, error wrapping, and query params.
2. **Server state → TanStack React Query**. Client state → Zustand. Do NOT put server-cache data (match lists, profiles) in Zustand.
3. **Zustand slices** follow the pattern in `store/slices.ts` — each slice is a `createXxxSlice` function receiving a `set` callback. New slices must follow this pattern.
4. **i18n**: every user-facing string MUST have keys in BOTH `ar.json` AND `en.json`. Use `next-intl`'s `useTranslations()` hook. Pages are under `[locale]` route group.
5. **RTL/LTR**: the root layout sets `dir` based on locale. Use Tailwind logical properties (`ms-*`/`me-*` instead of `ml-*`/`mr-*`) for bidirectional support.
6. **CSS classes**: Tailwind only. Order: layout → sizing → spacing → colors → typography → borders → effects. Use `brand-*` custom colors defined in `tailwind.config.ts`.
7. **5 UX states required per screen**: Loading (skeleton), Empty (illustrated CTA), Populated (normal), Error (retry button), Edge (form validation, disabled states).
8. **PWA**: `manifest.json` and `sw.js` must be kept in sync with new routes. Icons in `public/icons/`.
9. **Components**: `'use client'` directive ONLY when using hooks/state/event handlers. Server components by default.
10. **Form validation**: use Zod schemas + `react-hook-form` with `@hookform/resolvers`. No inline validation regex.
11. **NO mock data**: `dummy-data.ts` is removed. All data flows through the API. If the API returns empty/error, show the appropriate UX state.

## 4. Database Subagent — Data Infrastructure & Integrity

> **This section is binding for the database subagent.** When delegating database work, dispatch a dedicated agent whose sole responsibility is the PostgreSQL/Drizzle data layer. It must follow these rules.

### Responsibilities

1. **Schema design & evolution** — all schema changes go through `apps/api/src/database/schema.ts`. Review changes for normalization, correct types, and FK cascade behavior.
2. **Migrations** — `npm run db:generate` → review the generated SQL → `npm run db:migrate`. Never squash or delete applied migrations.
3. **GiST indexes** — PostGIS spatial indexes are manually defined in `apps/api/drizzle/gist_indexes.sql`. Apply after every new database or migration that touches geography columns.
4. **Seed data** — `apps/api/drizzle/seed.ts` must produce a realistic dev dataset (≥5 users, ≥3 venues, ≥5 pitches, ≥5 matches). The seed is idempotent (clears before inserting).
5. **Docker environment** — `docker compose up -d postgres redis` must yield a fully functional database. The DB is PostgreSQL 16 + PostGIS 3.5.
6. **Connection string** — `DATABASE_URL` in `.env` (from `.env.example`) points to the Docker PostgreSQL instance. SSL mode controlled by `SSL_MODE` env var.
7. **Data integrity** — all monetary values use `numeric(12,2)`, PostGIS columns use `geography(Point,4326)`, FK constraints use `ON DELETE CASCADE` where appropriate.

### Development Quickstart

```bash
# 1. Start the database
docker compose up -d postgres redis

# 2. Apply migrations + GiST indexes + seed
cd apps/api
cp .env.example .env                          # if not already done
npm run db:migrate                            # apply Drizzle migrations
psql "$DATABASE_URL" -f drizzle/gist_indexes.sql  # apply spatial indexes
npm run db:seed                               # insert dev data

# 3. Start the API
npm run dev
```

### Database Health Checks

- **PostgreSQL ready**: `docker compose exec postgres pg_isready -U koralink -d koralink`
- **PostGIS installed**: `docker compose exec postgres psql -U koralink -d koralink -c "SELECT PostGIS_Version();"`
- **GiST indexes present**: `docker compose exec postgres psql -U koralink -d koralink -c "\di *gist*"`
- **Seed data count**: `docker compose exec postgres psql -U koralink -d koralink -c "SELECT 'users' AS tbl, COUNT(*) FROM users UNION ALL SELECT 'venues', COUNT(*) FROM venues UNION ALL SELECT 'pitches', COUNT(*) FROM pitches UNION ALL SELECT 'matches', COUNT(*) FROM matches;"`

### Migration Workflow

```
Schema change needed
  ↓
1. Edit apps/api/src/database/schema.ts
  ↓
2. cd apps/api && npm run db:generate
   → Review generated SQL in drizzle/
  ↓
3. npm run db:migrate
   → Apply to dev database
  ↓
4. Update drizzle/seed.ts if new tables/columns added
  ↓
5. npm run db:seed
   → Verify seed still runs
  ↓
6. Commit: schema.ts + generated migration + updated seed
```

The seed MUST populate a realistic development dataset:

| Entity | Min Count | Key Data |
|--------|-----------|----------|
| Users | 5 | Diverse roles (Player, VenueOwner), skill levels, wallet balances |
| Venues | 3 | Different cities, amenities (parking, floodlights, etc.), is_approved=true |
| Pitches | 5 | Various sizes (5v5, 7v7, 11v11), surfaces (Grass, Artificial), environments |

## 5. Database Schema (Drizzle ORM)

### Tables (all in `apps/api/src/database/schema.ts`)

| Table | Key Columns | Notes |
|-------|------------|-------|
| `users` | id, phone (unique), full_name, handle (unique), wallet_balance, preferred_position, skill_level, role, karma_score, rating | Wallet uses `numeric(12,2)` |
| `venues` | id, owner_id → users, name, city, location (PostGIS geography) | CASCADE DELETE from users |
| `pitches` | id, venue_id → venues, name, size (enum), surface_type, hourly_rate | CASCADE DELETE from venues |
| `matches` | id, host_id → users, pitch_id → pitches, title, match_type, scheduled_at, price_per_player, max_players, location (PostGIS) | status: Open/Full/InProgress/Completed/Cancelled |
| `match_players` | id, match_id → matches, user_id → users, team (Home/Away), is_host, no_show | Unique constraint on (match_id, user_id) |
| `transactions` | id, user_id → users, type, amount, reference_type, idempotency_key (unique) | Append-only ledger |
| `match_messages` | id, match_id → matches, user_id → users, content | Indexed on match_id |

### Enums

`SkillLevel`, `UserRole`, `PitchSize`, `SurfaceType`, `Environment`, `MatchType`, `GenderRule`, `MatchStatus`, `TransactionType`, `ReferenceType`, `TransactionStatus`, `Team`

## 7. Code Quality Gates

Before marking ANY work complete:

1. **`npm run build` from root** must pass with zero errors.
2. **`npx tsc --noEmit -p apps/api/tsconfig.json`** must pass with zero errors.
3. **Tests pass**: `npx vitest run` from `apps/player-pwa` (85+ tests, 9+ files).
4. **No `any` types** in new code — use proper TypeScript types.
5. **No `console.log`** in production paths — use NestJS `Logger` for API.
6. **No hardcoded strings** in UI — all must be i18n keys in both `ar.json` and `en.json`.
7. **No raw `fetch`** in PWA components — always use `lib/fetcher.ts`.
