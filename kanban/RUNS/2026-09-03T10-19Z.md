- **Service (`apps/api/src/modules/users/users.service.ts`)**:
  - New `softDelete(userId)` — idempotent: a second call returns the existing `deleted_at`; the response includes `deleted_at + purge_at + restore_token` (a `purpose: 'restore'` JWT, 31d expiry). Also drops `push_subscriptions` rows on the first call (defense in depth — soft delete doesn't trigger CASCADE).
  - New `restoreUser(userId)` — idempotent: returns the populated profile on an active user; on a soft-deleted user inside the 30-day window, sets `deleted_at = NULL` and returns the populated profile (re-read outside the UPDATE, contract §2). Past the 30-day window: 400 "Restore window expired."
  - New `exportUserData(userId)` — 8-group JSON envelope: `exportedAt, schemaVersion, profile, matches, wallet, transactions, disputes, reports, activities, push_subscriptions`. Redaction rules: `push_subscriptions` drops `endpoint/p256dh/auth` (device crypto); profile drops `verification_status/banned_at/suspended_until` (admin-internal). 7-data-group shape per Reviewer B ask, expanded to 8 because we have both `joined` + `hosted` matches.
  - **Refactor** (Reviewer A #6): `searchUsers` now filters `deleted_at IS NULL AND banned_at IS NULL` (additive — closes a P2-14 prior bug that resurfaced in the run #8 review).
  - All 3 methods use Drizzle `isNull()` (not the broken `eq(col, null)` form) — gated by a PgDialect SQL assertion in the new spec.
- **Controller (`apps/api/src/modules/users/users.controller.ts`)**:
  - `DELETE /users/me` — calls `softDelete`
  - `POST /users/me/restore` — calls `restoreUser`
  - `GET /users/me/export` — calls `exportUserData`; sets `Content-Type: application/json; charset=utf-8` + `Content-Disposition: attachment; filename="koralink-export-YYYY-MM-DD.json"` so the PWA can download as a file
