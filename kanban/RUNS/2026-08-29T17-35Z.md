## Addendum (same session, after Reviewer A's full report landed)

Reviewer A's complete report surfaced two IMPORTANT defects in run #14's `24c7388` that the
truncated live summary had hidden:

1. **Caller signal disabled the 30s timeout entirely** (`api.ts:41`:
   `signal: options.signal ?? controller.signal` — any caller passing a never-aborting signal
   hung forever, silently reintroducing the perpetual-loading bug P2-24 exists to kill).
2. **Any AbortError was labeled "Request timed out"** — caller-initiated cancellations were
   misdiagnosed as timeouts.

Plus two hardcoded `aria-label="Close"` strings in `SlotManager.tsx:173,234`.

**Fixed this session (`0245e27`):** signals now linked via `AbortSignal.any([caller, timeout])`
with graceful fallback where unsupported; caller-initiated aborts rethrow untouched (only
timeout-originated aborts surface the timeout message); both close buttons use `common.close`
from the catalogs (`Close`/`إغلاق`). Bug-class sweep from Reviewer A: all 6 classes clean
repo-wide. Gates: admin tsc 0 · build 3/3 · admin service live 200. Board P2-24 row updated.
