## 6. Build & image contract (Slice E)

**`apps/api/Dockerfile.coolify`** (new file, ~20 lines):

```dockerfile
# Stage 1: deps + build
FROM node:20-bookworm-slim AS build
WORKDIR /repo
COPY package.json package-lock.json turbo.json ./
COPY apps/api/package.json ./apps/api/
COPY packages/ ./packages/ 2>/dev/null || true
RUN npm ci --no-audit --no-fund
COPY apps/api/ ./apps/api/
RUN env -u NODE_ENV npx turbo run build --filter=@koralink/api

# Stage 2: runtime
FROM node:20-bookworm-slim
WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends wget && rm -rf /var/lib/apt/lists/*
COPY --from=build /repo/apps/api/dist ./dist
COPY --from=build /repo/apps/api/package.json ./
COPY --from=build /repo/node_modules ./node_modules
ENV NODE_ENV=production
EXPOSE 3001
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \
  CMD wget -qO- http://127.0.0.1:3001/api/v1/health || exit 1
USER node
CMD ["node", "dist/src/main.js"]
```

**Coolify build settings (Slice E):**
- Build pack: `Dockerfile`
- Dockerfile path: `apps/api/Dockerfile.coolify`
- Build context: repo root (so COPY apps/api/dist works)
- Git branch: `main`
- Trigger: webhook on push to `main` (no auto-deploy — manual, like the staging script)

## 7. Migration contract (Slice F)

Run `scripts/migrate-vps.mjs` once after Slice F's first DB boot, with `DATABASE_URL` pointed at the Coolify DB (env: `MIGRATE_DATABASE_URL=postgresql://koralink:<pwd>@127.0.0.1:5433/koralink`).

**One-shot bootstrap:**
1. `docker exec koralink-db psql -U koralink -d koralink -c '\dt'` → empty
2. `cd apps/api && MIGRATE_DATABASE_URL=postgresql://koralink:<pwd>@127.0.0.1:5433/koralink node --env-file=.env scripts/migrate-vps.mjs` (uses the staging `.env` for secrets, override the URL)
3. `docker exec koralink-db psql -U koralink -d koralink -c '\dt'` → all tables present
4. `docker exec koralink-db psql -U koralink -d koralink -c "select count(*) from drizzle.__drizzle_migrations;"` → matches `drizzle/*.sql` count
5. `psql postgresql://koralink:<pwd>@127.0.0.1:5433/koralink -c "select count(*) from users;"` → 0 (clean start, no data yet)

Slice F runbook documents: import-from-staging is a one-shot runbook (you copy staging → Coolify DB for a "warm start" demo), default = empty prod.

## 8. Rollback contract (Slice H)

**Render rollback path (T2, ≤2 min):**
1. Vercel: `NEXT_PUBLIC_API_URL` → `https://koralink-api.onrender.com/api/v1` (T2 env edit)
2. Vercel: redeploy (button)
3. Done. PWA now points to Render. Coolify can stay up as the future home; Render keeps serving until Coolify is ready to receive traffic again.

**Coolify rollback path (T1, ≤5 min):**
1. Cloudflare CNAME `api.koralink.sa` → Render URL (Cloudflare dashboard quick-edit or T1 CF API)
2. Friends see Render instantly behind same hostname.
3. Coolify can stay running or be stopped; no data loss.

**Both directions pre-verified by `env-matrices.md` (this same docs set).**
