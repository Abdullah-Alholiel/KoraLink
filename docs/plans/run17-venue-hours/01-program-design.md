# Run #17 — Venue operating hours (P1-25) — Gates 0-3 compact

## Gate 0 — Retro (area audit)
`venues` table (schema.ts:220-250) has zero hours/blockout columns (grep `open_hours|operating` → 0).
`generateSlots`/`createSlot` (partner.service.ts:511-610) clamp only `end > start` — nothing ties
slot generation to venue hours, so partners can publish 3am slots at a closed venue and players can
book them. Venue profile API surfaces: partner `getVenues` (no hours), player `findNearby`
(venues.service.ts:32-94), player `findOne` (:99-129). Recent commits in the area: P1-26 partner
matches (4e7ad44) — pattern to follow: DTO whitelisting + Riyadh-local reasoning + ownership via
`assertPitchAccess` (reused unchanged here).

## Gate 1 — Product
**Problem:** venues are treated as 24/7; Saudi venues close for prayer/night/midday and players
book slots a venue can never honor.
**User stories:** as a venue owner I set daily opening/closing hours (and mark a day closed);
as a player I see whether a club is open right now; as the platform I never generate slots
outside the venue's hours for that weekday.
**In scope:** schema columns (per-day hours + closed flags, simple ints + booleans), partner
update endpoint, slot generation/creation clamping, player-facing `is_open_now` + badge,
admin edit UI (venue form). **Out of scope:** special-date overrides/holidays/prayer calendars
(Riyadh prayer times API — future cycle), timezone anything (single Asia/Riyadh product),
per-pitch hours.
**Success criteria:** hours persisted + returned by all 3 read paths; `generateSlots` skips
out-of-hours windows (reported as skipped); `createSlot` 400s out-of-hours; clubs page shows
Open/Closed badge live.

## Gate 2 — Architecture
- **DB:** `venues` += `open_hour smallint NOT NULL DEFAULT 8`, `close_hour smallint NOT NULL
  DEFAULT 23` (24h Riyadh-local, close exclusive, close 24 = midnight), 7 × `closed_day_N
  boolean NOT NULL DEFAULT false` (N=0 Sunday … 6 Saturday, PG/JS convention-aligned).
  Migration generated by drizzle-kit AFTER code commit (Phase 4.5 sequencing).
- **API (partner):** `PATCH /partner/venues/:id` gains optional `open_hour/close_hour
  (0-24, close > open, close 24 allowed) + closed_day_0..6` in `UpdateVenuePartnerDto`;
  `updateVenue` copies them into `updates`. `generateSlots`: per-date day-of-week check →
  if `closed_day_N`, skip the whole date; clamp the window to `[open_hour, close_hour]` →
  no slots outside → counted in `skipped`. `createSlot`: same clamp math → 400 with an
  explicit message when fully outside/closed.
- **API (player):** `findNearby` SELECT += `open_hour, close_hour, is_closed` (per-today
  boolean via `EXTRACT(DOW)` — clean additive AND-free SELECT additions, list predicate
  untouched) + `is_open_now` boolean expression; `findOne` += same 4 fields. List
  WHERE/order untouched.
- **PWA:** `VenueApi` += the 4 fields; clubs page renders an Open/Closed badge (green/gray)
  next to the address line; i18n `clubs.openNow` / `clubs.closedNow` en+ar.
- **Admin:** venues edit form gains hours inputs + 7 closed-day checkboxes → sent on save.

## Gate 3 — Program design (contracts)
**Partner PATCH (partial, all optional)** — request extras:
```json
{ "open_hour": 8, "close_hour": 24, "closed_day_5": true }
```
400s: `open_hour`/`close_hour` outside 0-24; `close_hour <= open_hour` (except close 24).
**Player `GET /venues` row (delta)**:
```json
{ "open_hour": 8, "close_hour": 24, "is_closed": false, "is_open_now": true, ... }
```
`is_open_now` ≡ `NOT closed_day_<today> AND open_hour <= <riyadh_hour> AND <riyadh_hour> < close_hour`
(with `close_hour = 24` covering the 23:xx hour). `GET /venues/:id` returns the same 4 fields.
**generateSlots response (unchanged shape):** `{ created, skipped }` — out-of-hours/closed-day
slots now land in `skipped` (before: generated).
