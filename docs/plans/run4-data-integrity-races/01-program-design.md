# Run #4 — Program Design (Gates 1-3 compact)

## Problem
Concurrent admin/report actions can double-pay settlements, double-generate pending payouts, duplicate reports; unbanned users receive a "suspended" notification.

## Slices (vertical, in order)

### Slice 1 — settlement `pay` TOCTOU (backend, no migration)
`AdminSettlementsService.pay` (settlements.service.ts:65-91):
- Change UPDATE to `WHERE and(eq(settlements.id, id), eq(settlements.status, 'pending'))` and read the returned row via `.returning({ id: settlements.id })`.
- If no row returned → `BadRequestException('Only pending settlements can be paid.')`.
- Keep the `before`/`after` audit; `after` = `this.findOne(id)` (already compliant, called outside tx).
- Keep `before.status !== 'pending'` pre-check for the common case (clearer error, still race-safe).

### Slice 2 — `generatePending` + `reports.create` dedup (backend + migration 0018)
**Schema (schema.ts):**
- `settlements` table index fn → add `uniqueIndex('settlements_venue_period_uidx').on(t.venue_id, t.period_start)`.
- `reports` table index fn → add partial unique `uniqueIndex('reports_open_subject_uidx').on(t.reporter_id, t.subject_type, t.subject_id).where(sql\`${t.status} IN ('open','reviewing')\`)`.

**Service (settlements.service.ts:99-150):** wrap the per-venue insert loop in `this.db.transaction(async (tx) => {...})`; insert with `.onConflictDoNothing()` (unique `venue_id+period_start`); count only actually-inserted rows; return `{ generated, settlements }` from the inserted rows.

**Service (reports.service.ts:19-56):** replace the `select-then-insert` dedup with an in-transaction insert using `.onConflictDoNothing()` targeting the partial unique index; if no row inserted → `BadRequestException('You have already reported this subject.')`. Reuse the existing `select` as a fast-path pre-check (keeps the friendly message) but the unique index is the real guard.

### Slice 3 — unban verb `account_unbanned` (full-stack)
- **schema.ts:** `activityVerbEnum` add `'account_unbanned'`.
- **activities.service.ts:** `ActivityVerb` add `'account_unbanned'`; `DIRECTED_VERBS` add `'account_unbanned'`.
- **users.service.ts:191:** `verb: updates.banned_at ? 'account_banned' : 'account_unbanned'`.
- **PWA useFeed.ts:** `FeedVerb` union add `'account_unbanned'`.
- **PWA ActivityCard.tsx:** `VERB_ICON.account_unbanned = ShieldCheck` (or UserCheck); `VERB_LABEL.account_unbanned = 'feed.accountUnbanned'`.
- **PWA NotificationSheet.tsx:** icon + `notifications.accountUnbanned` label.
- **PWA NotificationProvider.tsx:** toast map `account_unbanned: t('accountUnbanned')`.
- **i18n ar.json + en.json:** `feed.accountUnbanned`, `notifications.accountUnbanned`, `accountUnbanned`.

## Contract verification checklist (Gate 3)

- [ ] `pay` mutation returns `findOne(id)` (populated, outside tx) — kept.
- [ ] `pay` is idempotent under concurrency (conditional `WHERE status='pending'` + row-count check).
- [ ] `generatePending` never double-inserts (unique index + `onConflictDoNothing`).
- [ ] `reports.create` never double-inserts open reports (partial unique index + `onConflictDoNothing`).
- [ ] New verb `account_unbanned` present in DB enum, API type, and all 4 FE maps + both i18n files.
- [ ] No `::uuid` casts (all ids varchar(36)); no `eq(col, null)`; NULL handling via `isNull`.
